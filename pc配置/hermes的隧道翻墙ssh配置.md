# 服务器通过 SSH 反向隧道代理使用指南

本文档详细说明如何通过 SSH 反向隧道，让腾讯云服务器借助本地 Windows 电脑的 Clash 代理访问外网，包含原理、配置步骤与使用方法。

### 2. 关键概念拆解

表格

| 组件              | 作用              | 说明                                          |
| :-------------- | :-------------- | :------------------------------------------ |
| **SSH 反向隧道**    | 建立服务器与本地电脑的加密通道 | 通过 `ssh -R` 参数实现，将服务器的 1080 端口映射到本地 7897 端口 |
| **服务器代理入口**     | 服务器侧的请求转发点      | 端口 `1080`，服务器内所有网络请求先发送至此，再通过隧道转发           |
| **本地 Clash 代理** | 实际处理外网请求的代理     | 端口 `7897`，负责接收隧道转发的请求并访问外网                  |

### 3. 为什么需要 `export http_proxy`？

- SSH 反向隧道只是搭好了 “数据通道”，但服务器里的 `curl`、`apt` 等工具默认直连外网，不知道这条通道的存在。
- `export http_proxy=http://127.0.0.1:1080` 是给这些工具发送 “指令”：所有 HTTP/HTTPS 请求都发送到 `127.0.0.1:1080`（服务器代理入口），再走隧道转发。

## 二、前置条件

1. 本地 Windows 电脑已安装 **Clash Verge**，并配置好可正常访问外网的节点。
2. 腾讯云 Ubuntu 服务器可正常 SSH 连接，本地电脑与服务器网络互通。
3. 服务器默认用户名：`ubuntu`（腾讯云 Ubuntu 系统默认），端口：`22`。

---

## 三、配置步骤

### 步骤 1：建立 SSH 反向隧道（本地电脑操作）

#### 方式 1：PowerShell 命令行

打开 PowerShell，执行以下命令，输入服务器密码登录：

powershell

```
ssh -R 1080:localhost:7897 ubuntu@111.229.133.120
```

- `-R 1080:localhost:7897`：反向隧道参数，含义为「服务器的 1080 端口映射到本地的 7897 端口」
- `ubuntu@111.229.133.120`：服务器用户名与公网 IP

#### 方式 2：Xshell 图形化配置

1. 新建会话：主机填写服务器公网 IP，端口 `22`，用户名 `ubuntu`。
2. 进入「连接 → SSH → 隧道」，点击「添加」：
    
    - 类型：**远程（传入）**
    - 源主机：`localhost`
    - 侦听端口：`1080`
    - 目标主机：`localhost`
    - 目标端口：`7897`（Clash 的混合端口）
    
3. 保存会话并连接服务器。

### 步骤 2：服务器侧配置代理开关（服务器终端操作）

1. 先清理旧配置（避免冲突）：

bash

运行

```
sed -i '/http_proxy/d' ~/.bashrc
sed -i '/https_proxy/d' ~/.bashrc
```

2. 添加一键代理开关别名：

bash

运行

```
echo "alias proxy-on='export http_proxy=http://127.0.0.1:1080 https_proxy=http://127.0.0.1:1080'" >> ~/.bashrc
echo "alias proxy-off='unset http_proxy https_proxy'" >> ~/.bashrc
```

3. 让配置立即生效：

bash

运行

```
source ~/.bashrc
```

## 四、日常使用方法

### 1. 开启代理（隧道连接正常时）

在服务器终端执行：

bash

运行

```
proxy-on
```

### 2. 测试代理是否生效

执行以下命令，若返回 `HTTP/1.1 200 Connection established`，则代理正常：

bash

运行

```
curl -I https://www.google.com
```

### 3. 关闭代理（隧道断开或无需代理时）

执行以下命令，服务器将恢复原生公网直连：

bash

运行

```
proxy-off
```

### 4. 检查当前代理状态

bash

运行

```
# 查看当前 http_proxy 变量值
echo $http_proxy
```

- 输出 `http://127.0.0.1:1080`：代理已开启
- 无输出：代理已关闭

## 五、常见问题与注意事项

### 1. 隧道断开后，代理会自动切回直连吗？

- **不会自动切换**：如果隧道断开，`127.0.0.1:1080` 代理端口失效，但 `http_proxy` 环境变量仍存在，服务器请求会一直报错。
- 解决方法：执行 `proxy-off` 手动关闭代理，恢复直连。

### 2. 为什么服务器里不能直接用 7897 端口？

- `7897` 是本地 Windows 电脑上 Clash 的端口，服务器无法直接访问本地电脑的端口。
- 服务器里只能使用 `1080` 端口（SSH 隧道映射的代理入口），请求会自动通过隧道转发到本地的 7897 端口。

### 3. 复制命令时出现乱码怎么办？

- 问题原因：复制时包含了文本编辑器的控制字符（如 `^[[200~`），终端会将其视为命令的一部分导致报错。
- 解决方法：直接复制本文档中纯文本格式的命令，避免复制带格式的内容，在终端右键粘贴即可。

### 4. 代理仅对当前终端生效吗？

- 是的：`proxy-on` 设置的环境变量仅对当前 SSH 会话的终端生效。
- 新的 SSH 会话或服务器重启后，代理配置会失效，需要重新执行 `proxy-on`。

## 六、进阶补充

### 1. 让 apt 包管理器走代理

单独配置 apt 代理，仅安装软件时走隧道：

bash

运行

```
sudo nano /etc/apt/apt.conf.d/99proxy
```

写入以下内容：

plaintext

```
Acquire::http::Proxy "http://127.0.0.1:1080";
Acquire::https::Proxy "http://127.0.0.1:1080";
```

保存退出后，`apt update` 会自动走代理。

### 2. 隧道断开后，如何保持代理稳定？

可以使用 `autossh` 实现自动重连（需在本地电脑安装）：

bash

运行

```
autossh -M 0 -R 1080:localhost:7897 ubuntu@111.229.133.120
```

- `-M 0`：禁用自动心跳检测，避免端口冲突
- 隧道断开后会自动重连，无需手动操作。

## 七、风险提示

1. 合规风险：微信云服务等平台禁止使用代理访问境外服务，长期使用可能触发风控限制。
2. 隐私风险：服务器所有网络请求会经过本地电脑，需确保本地网络环境安全。
3. 稳定性风险：代理依赖本地电脑与网络，关机、断网会导致隧道断开，影响服务器网络。
