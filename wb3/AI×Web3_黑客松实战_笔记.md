# 第一章：基础概念扫盲（先搞懂这些再往下看）

## 你必须知道的术语

| 术语                  | 大白话解释                              |
| ------------------- | ---------------------------------- |
| **钱包（Wallet）**      | 管你加密货币私钥的软件，不是装钱的皮夹子               |
| **私钥（Private Key）** | 一串超级长的密码，谁拿到谁就能动你的钱                |
| **MPC 钱包**          | 把私钥切成两片（手机存一片、云端存一片），两片凑一起才能签名     |
| **多签钱包（Multi-sig）** | 需要 N 把钥匙中的 M 把才能操作，类似保险柜要 3 把钥匙同时转 |
| **AI Agent**        | 能自己干活的 AI，不只是聊天，能帮你执行操作（转账、下单）     |
| **Policy（策略）**      | 给 AI Agent 定的"家规"——可以做什么、做多少、做多久   |
| **CLI**             | 命令行工具，黑框框里敲命令让电脑干活                 |
| **API / SDK**       | API = 两个程序对话的接口；SDK = 别人写好的工具箱     |
| **EVM 兼容**          | 所有用以太坊技术的链都认同一套规则，地址通用             |
| **黑客松 / Hackathon** | 黑客 + 马拉松，开发者限时 48 小时做出一个能用的产品      |

# 第三章：MPC 钱包技术原理 ⭐ 全场最核心

## 3.1 传统钱包怎么工作的？（对比用）

> **原文：** "小狐狸（MetaMask）创建钱包，私钥存在你的浏览器里，是一个单点的概念。"

```
你创建一个钱包
      ↓
你的电脑上生成一个完整的私钥
      ↓
私钥存在你的浏览器本地
      ↓
你想转账 → 浏览器用私钥签名 → 广播到区块链
      ↓
坏处：电脑中木马 → 黑客偷私钥 → 钱没了
```

**类比：** 就像把银行卡密码写在纸上贴在电脑屏幕上。电脑安全就没问题，但有人进了你家门一眼就能看到。

## 3.2 MPC 的革命性设计

> **原文：** "MPC 是说在你的手机或者你的服务端这边各有一片。"

**MPC = Multi-Party Computation（多方计算）**，把私钥切成两片分开存：

```
完整私钥
   ↓
切成两片碎片
   ↓
┌─────────────┐    ┌─────────────┐
│  碎片A       │    │  碎片B       │
│  （你手机）   │    │  （云端服务器）│
└─────────────┘    └─────────────┘
   ↓                    ↓
     需要"见面协商"才能签名
     进行好几轮加密通信
     最终产出一个签名结果
   ↓                    ↓
✅ 只偷到手机 → 没服务器碎片，签不了名
✅ 只黑进服务器 → 没你手机碎片，也签不了名
```

**超级类比：** 一个保险柜需要两把钥匙同时转才能打开——
- 传统钱包 = 一把钥匙在你手里，谁拿到就能开
- MPC 钱包 = 你拿一把钥匙，银行拿一把钥匙，**必须同时插入同时转动**

## 3.3 最关键的一句话

> **原文：** "在整个签名过程中永远不会有任何一方有完整的私钥，也不会在任何地方生成一个完整的私钥，但它最终能够签名出一个等同于那个签名的签名。"

**三层拆解：**

**第一层：过程中没有完整私钥**
传统签名：私钥完整出现 → 用它签名
MPC 签名：两片碎片分别计算 → 把计算结果合并 → 产出签名

**第二层：结果跟传统签名完全一样**
区块链那边**看不出区别**——它看到的就是合法签名，不会知道你是 MPC 还是传统钱包。

**第三层：安全性的质变**
- 传统：攻破 **一个点** 就行
- MPC：需要同时攻破 **两个点**（你手机 + 服务器）

## 3.4 实际好处：双向制衡

### 平台不能偷你的钱

> **原文：** "作为平台方，没办法单独在用户不配合的情况下盗取用户资产。"

平台有碎片 B，但没有你的碎片 A。想卷款跑路？技术上做不到。这叫 **Trustless（无需信任）**——你不用相信平台是好人，因为他们想做坏事也做不了。

### 你也得经过风控

> **原文：** "用户要服务端签名，服务端签名就要通过风控引擎。"

你有碎片 A，但没有碎片 B（在服务器上）。想转一大笔钱？风控引擎检查 → 发现异常 → 拒绝签名 → 交易失败。

**双向制衡就是 MPC 的精髓——谁都不能为所欲为。**

# 第四章：AI Agent 安装与配对流程

## 4.1 装了什么？

> **原文：** "去官网复制一段命令，粘贴到终端里运行。"

装的东西：
1. **CW 钱包引擎**（核心程序）
2. **CLI 命令行工具**
3. **脚本工具集**
4. **配置文件**

就像从官网下载微信安装包双击安装，只不过这里用的是命令行（黑框框）。

## 4.2 两种模式

### 模式一：自由模式（不配对手机）

```
安装 → 创建钱包 → Agent 可以随便操作
✅ 优点：简单、快捷、AI 效率高
❌ 缺点：没有人类监督，AI 被黑/犯糊涂 → 钱可能没了
适合：小金额、测试、完全信任 AI
```

### 模式二：受控模式（配对手机 App）⭐ 推荐

```
安装 → 创建钱包 → 配对手机 App → 配置 Policy
Agent 想操作？→ 提交申请 → 你手机审批 → 通过才执行
✅ 优点：每笔操作都要你点头，安全
❌ 缺点：慢，每次要等人审批
适合：大金额、正式使用
```

## 4.3 配对过程详解

> **原文：** "Agent 会生成一个八位数字配对码，你在手机里输入这个码。"

```
你的电脑（Agent）
   ↓ 生成 8 位配对码
   ↓ 显示在屏幕上
   
你的手机（App）
   ↓ 你手动输入这 8 位数字
   ↓ App 跟 Agent 建立安全连接
   
开始 MPC 密钥协商
   ↓ 手机和服务器来回通信好几轮
   ↓ 各自生成一部分密钥碎片
   ↓ （无任何一方看到完整私钥）
   
配对完成 ✅
```

### 为什么这么慢？

| 方式 | 耗时 | 原因 |
|---|---|---|
| 传统本地签名 | <1 秒 | 私钥就在本地 |
| MPC 签名 | 2~10 秒 | 需要多轮通信协商 |

**类比：** 
- 传统签名 = 你一个人签个字
- MPC 签名 = 你跟另一个人隔着一堵墙，要互相喊话确认

## 4.4 ⚠️ 备份！备份！备份！

> **原文：** "这个备份文件相当于就是你的私钥。一旦丢了，同时手机也丢了，我们作为平台方也没有办法帮你恢复——这个跟私钥丢了是一样的。"

**三个故事：**

❌ **故事一（反面）：** 配对了手机，没备份。三个月后手机丢了。买新手机下载 App——钱包里的钱**全没了**。为什么？私钥碎片只存在旧手机里。

✅ **故事二（正确）：** 配对了手机，立即做本地文件备份（存到电脑里）。手机丢了？重新下 App，导入备份文件，钱包回来了。

❌ **故事三（最惨）：** 你备份了，但备份文件存在手机本地。手机丢了 = 备份也丢了。

**正确做法：**
```
配对完成 →
立即备份 →
备份文件存到 2~3 个不同地方：
  ① 电脑硬盘
  ② 云盘（iCloud / 百度网盘）
  ③ U 盘冷备份（不联网）
```

> ⚠️ 在 Web3 世界里，没有"忘记密码点找回"这回事。私钥丢了就是永久丢了，**上帝也救不了你**。

# 第五章：Policy 权限系统 ⭐ 安全核心

## 5.1 Policy 是什么？

> **原文：** "Agent 发起一件事，需要先经过用户确认，达成一个契约。"

**Policy = AI 的行为准则 + 授权书**

```
没有 Policy：
  像把银行卡和密码都给了一个陌生小孩

有 Policy：
  像给小孩发了一张"购物清单"：
    可以买：牛奶、面包、鸡蛋
    不能买：烟酒、游戏机
    总额度：不超过 100 元
```

## 5.2 Policy 里写了什么？

AI Agent 自动生成，不需要你手动敲：

```json
{
  "目的": "把 ETH 换成 USDC",
  "目标平台": "Uniswap 交易所",
  "金额上限": "0.1 ETH",
  "频率": "24 小时内 1 次",
  "有效期": "7 天后自动失效",
  "状态": "待你手机审批"
}
```

## 5.3 自动失效机制

> **原文：** "为什么要自动失效？万一密钥泄露了，设置一个过期的可以减少风险窗口。"

**场景对比：**

❌ **没有自动失效：**
你给 Agent 授权"可以任意操作" → 三个月后 Agent 被黑客攻破 → 黑客利用未过期的授权把钱全转走

✅ **有自动失效：**
你给 Agent 授权"7 天内有效" → 第 8 天自动作废 → 第 10 天 Agent 被黑 → 授权已过期 → **一分钱都动不了**

**就像酒店房卡**——check-out 时间一到自动失效。别人捡到你的房卡也进不了房间。

## 5.4 完整审批流程

```
1️⃣ AI Agent："我想做一笔交易"
2️⃣ AI 自动生成 Policy（申请权限）
3️⃣ Policy 提交到后端
4️⃣ 手机收到推送通知
5️⃣ 打开手机 App 查看详情
6️⃣ 跟你的原始指令对比一下
7️⃣ AI 洞察引擎帮你分析风险
8️⃣ 你点"批准" → 交易执行
   你点"拒绝" → 交易取消
```

## 5.5 AI 洞察引擎 ⭐ 小白救星

> **原文：** "AI 洞察是我们服务端的一个大模型 AI，它会判断 Policy 是否合理、有哪些风险，提示出来。"

**你看不懂 Policy？没关系，AI 帮你审 AI：**

```
你说："帮我把 0.1 ETH 换成 USDC"
       ↓
Agent 生成 Policy："允许调用 Uniswap，转账上限 10 ETH..."
       ↓
AI 洞察引擎分析：
  ⚠️ "用户说 0.1 ETH，但 Policy 申请 10 ETH
     金额不匹配，存在风险，建议拒绝"
       ↓
你在手机上看到警告 → 拒绝 ❌
```

# 第六章：Developer 模式（程序化集成）

## 6.1 什么时候用？

| | Agent 模式 | Developer 模式 |
|---|---|---|
| **谁主导** | AI 自己决定 | 程序员写死流程 |
| **灵活性** | 高，AI 随机应变 | 低，只能按预设来 |
| **安全性** | 靠 Policy + AI 洞察 | 代码写死了更可控 |
| **适合** | AI 投资顾问、自动交易 | 定期扣款、工资发放、DApp 后端 |

**类比：**
- Agent 模式 = 私人管家，你说"帮我管好钱"，他自由发挥
- Developer 模式 = 自动转账，每月 1 号转 5000，不增不减

## 6.2 装完后的目录结构

安装 CLI 后，你电脑上会有：

```
项目目录/
├── cw/
│   ├── cw.exe          ← 主程序
│   ├── config.yaml     ← 配置文件
│   └── profiles/       ← 钱包们
│       ├── wallet_1/   ← 第一个钱包
│       │   ├── key     ← 密钥对
│       │   ├── address ← 钱包地址
│       │   └── db.sqlite ← 数据库
│       ├── wallet_2/   ← 第二次安装产生的
│       └── wallet_3/   ← 第三次安装产生的
```

> ⚠️ 每次从官网复制命令都会**新建一个钱包**，不覆盖旧的。用久了可能有很多个，记得用 `cw list` 查看和管理。

## 6.3 纯 API 集成

> **原文：** "第一步调一个 API 创建 API Key，这个返回值要记住，后面的请求都需要它。"

**API Key = 你的身份凭证：**

```
去银行办业务：
  第一步：出示身份证 → 银行给你一个号
  后面每一步：报这个号 → 银行知道你是谁

API 调用也一样：
  第一步：注册 → 拿到 API Key
  后面每次请求：带上 API Key → 服务器知道你是谁
```

> ⚠️ API Key 丢了 = 别人能冒用你的身份。像丢了身份证一样严重。

### 为什么永远需要本地进程？

> **原文：** "你可以不下载 CW，但还是需要下载一个东西做签名，永远需要一个进程跑着。"

你的服务器想发起交易 → 需要签名 → 发送请求给本地的小进程 → 这个进程持有你的密钥碎片 → 跟服务器 MPC 通信 → 协同完成签名 → 交易广播到区块链。

**即使纯 API 集成，也必须有个地方跑着签名进程**——你自己的服务器、电脑、或云函数都行。

## Q2：AI Agent 能做什么？（最有意思的部分）

> **答：** "两个热门的：AI + 支付，和链上套利。"

### 方向一：AI + 支付

```
普通 AI：
  你："帮我总结这篇论文"
  AI："抱歉，在付费平台，我访问不了"

有支付能力的 AI Agent：
  你："帮我总结这篇论文"
  AI：自动花 $0.02 调用付费 API → 拿论文 → 总结给你
      全程不需要你手动掏钱
```

更疯狂的用法：
- AI 去雇真人完成任务（上 Fiverr 找设计师画图）
- AI 之间互相买卖服务
- AI 自动订阅付费软件并管理订阅

### 方向二：链上套利

预测市场（Prediction Market）= 去中心化赌场，可对任何事件下注：

```
事件："2026 年 9 月前美国政府能证明外星人存在吗？"
赔率："是" = 1:10（押 1 块赢 10 块）
       "否" = 1:1.1（押 10 块赢 11 块）

AI 自动搜索全网新闻、科学论文、政府声明
判断："几乎不可能" → 自动下注"否"
如果对了 → 稳定赚一点
```

**核心逻辑：** AI 24 小时不停寻找"确定性机会"，做高频低风险套利。

## Q3：MPC 跟多签钱包到底有什么区别？

> **答：** "多签是把钱包变成几把钥匙，凑够数量就能开。MPC 不是拼装凑数，有更复杂的密码学交互。"

**多签钱包：** 3 个人各有一把**完整钥匙**，凑够 2 把就能开柜。被偷一把 = 小偷拿到了一把完整的钥匙。

**MPC 钱包：** 一张 100 元钞票撕成两半，你拿一半银行拿一半。单独拿一半 = 废纸。而且过程中从未还原出"完整的那张钞票"。

## Q5：Permit2 / EIP-712 支持吗？

**Permit2：** 跟 Policy 引擎结合还不够好，**还没做好**。

# 📚 全篇总结

## 一张图看懂全部流程

```
你用官网命令装好 CLI
        ↓
Agent 帮你创建钱包（自动完成）
        ↓
        ├── 方案 A：不配对手机
        │       ↓
        │   Agent 自由操作，无风控
        │   适合小额/测试
        │
        └── 方案 B：配对手机 App ⭐ 推荐
                ↓
          生成 8 位配对码
                ↓
          手机输入 → MPC 密钥协商（几秒~几十秒）
                ↓
          ⚠️ 立即备份！(iCloud / 本地文件)
                ↓
          配置 Policy（定规矩）
                ↓
          Agent 发起交易 → 你手机审批 → 执行
```

## 给小白的重要提醒

1. **测试环境不要放真钱！** 登录名太简单别人也能登进去
2. **一定要备份！** MPC 钱包丢了就永久丢了，平台也救不了你
3. **Policy 不是一次性的** — 可以设长期规则（每月自动转 0.1 ETH）
4. **MPC 比普通签名慢** — 每次几秒钟，不是毫秒级
5. **鸿蒙用户注意** — 不是原生支持，建议用苹果手机测试
6. **不懂的有地方问** — 官方微信群有工程师值班
