### 二、常见赛道分类

#### 赛道 1：AI Agent × DeFi

- **描述**：用 AI Agent 自动化 DeFi 操作（套利、仓位管理、清算保护）
- **关键技术**：LLM 决策 + 链上数据索引 + 合约交互
- **代表方向**：
  - 智能投顾 Agent
  - 跨链套利机器人
  - 风险监控与自动对冲

#### 赛道 2：AI Agent × 社交 / 社区

- **描述**：AI 驱动的链上社交、社区治理辅助
- **关键技术**：Agent 记忆系统 + 链上身份 + 自主决策
- **代表方向**：
  - DAO 治理助手（提案分析、投票建议）
  - 链上声誉系统 + AI 推荐
  - 自主运营的 AI 社区成员

#### 赛道 3：AI × 开发工具 / 基础设施

- **描述**：用 AI 降低 Web3 开发门槛
- **关键技术**：代码生成 + 合约审计 + 自然语言→合约
- **代表方向**：
  - 自然语言生成 Solidity 合约
  - AI 辅助合约安全审计
  - 链上数据分析可视化工具

#### 赛道 4：AI × 内容创作 / NFT

- **描述**：生成式 AI 与 NFT 的结合
- **关键技术**：多模态模型 + 链上元数据 + 版权验证
- **代表方向**：
  - 动态 NFT（根据链上事件改变元数据）
  - AI 生成艺术 + 去中心化分发
  - 音乐/视频生成 x 版权上链

#### 赛道 5：AI × 隐私计算 / 去中心化推理

- **描述**：在保护隐私的前提下使用 AI 模型
- **关键技术**：TEE、ZKML、联邦学习
- **代表方向**：
  - 链上隐私推理
  - 可验证的 AI 模型推理
  - 去中心化模型市场

### 三、黑客松实战流程

```
赛前准备 ──→ 选题定方向 ──→ 团队组建 ──→ 快速开发 ──→ 演示交付
```

#### 阶段 1：赛前准备（赛前 1~2 周）

```
□ 了解主办方赛道说明 + 评分标准
□ 研究往届获奖项目，找共性
□ 储备基础技术栈（Agent 框架 / 合约模板）
□ 提前准备好开发环境 + API Key
□ 构思 2~3 个候选方向
```

#### 阶段 2：选题定方向（赛前 / 第一天）

| 选择原则 | 说明 |
|----------|------|
| 🎯 **痛点真实** | 解决的问题是真实的，不只是玩概念 |
| 🔧 **技术可及** | 团队能力范围内，48h 能出 demo |
| 📈 **有叙事空间** | 评委能快速理解价值，故事好讲 |
| 💡 **差异化** | 和往届项目不同，或者有明显改进 |

#### 阶段 3：团队组建

```
推荐的团队配置（4~5 人）：

  ├─ 1 名 AI/Agent 工程师 ── LLM 集成、RAG、Agent 逻辑
  ├─ 1 名 合约工程师 ───── Solidity / 链上交互
  ├─ 1 名 前端工程师 ──── 用户界面 + 钱包集成
  ├─ 1 名 PM/Designer ─── 产品设计 + 演示制作
  └─ (可选) 1 名 全栈补位 ── 哪里需要填哪里
```

#### 阶段 4：快速开发

```
Day 1 上午：确定方向 + 分工 + 搭建脚手架
Day 1 下午：核心功能并行开发
Day 2 上午：集成联调 + 修复阻塞 bug
Day 2 下午：Demo 打磨 + 准备演示材料
```

**关键原则：**

- **先跑通再优化** — Demo 能跑比完美更重要
- **降低复杂度** — 能用现成 API 就别自己造
- **保留演示兜底** — 如果核心功能没跑通，准备录播或 slide

#### 阶段 5：演示交付

一个优秀的黑客松演示应该包含：

```
1. 一句话说清做什么
2. 现场 Demo（30~60 秒核心流程）
3. 技术架构亮点（1~2 个）
4. 商业模式/代币经济（如果有）
5. 未来 roadmap
6. 团队介绍
```

### 四、评审标准解析（典型权重）

| 维度 | 权重 | 要点 |
|:----:|:----:|------|
| 💡 **创新性** | ~30% | 想法是否新颖？有没有差异化？ |
| 🔧 **技术难度** | ~25% | 技术实现是否有挑战性？ |
| 📊 **完成度** | ~20% | Demo 能跑吗？体验流畅吗？ |
| 📈 **商业价值** | ~15% | 有没有真实需求？能落地吗？ |
| 🎤 **演示效果** | ~10% | 故事讲得好不好？ |

### 五、常见踩坑与避坑指南

| 常见坑 | 后果 | 怎么避免 |
|--------|------|----------|
| 🕳 **选题太大** | 48h 做不完，demo 跑不通 | 砍到最核心的一个功能 |
| 🕳 **团队缺人** | 某块没人做，进度卡死 | 赛前在 Discord 提前组队 |
| 🕳 **过度依赖 API** | 限流/挂了 demo 炸了 | 准备本地 fallback |
| 🕳 **最后才做 UI** | 演示时评委看不清 | 先搭好基础 UI 再连逻辑 |
| 🕳 **忽略链上交互** | 合约部署出错时间不够 | 提前写好测试合约 |
| 🕳 **演示只讲 PPT** | 没有现场 Demo 印象差 | 哪怕录屏也行，必须有演示 |
