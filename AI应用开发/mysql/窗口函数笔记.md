# 窗口函数（Window Function）完整笔记

> 对应《尚硅谷大模型技术之 MySQL2.0》"窗口函数"章节
> 配套数据：`atguigu` 库的 `t_employee` 表（练习前先 `use atguigu;`）

---

## 一、窗口函数是什么？为什么要学它？

**一句话：窗口函数 = "不压缩行数"的分组函数。**

分组函数有个坏脾气：一出手，行数就变少（15 行变 1 行）。

```sql
select ename, salary, max(salary) from t_employee;
-- 报错！ename 有 15 行，max(salary) 只有 1 行，对不上
```

但我经常**既要 15 行原样显示，又想知道"最高薪资是多少"**，用来每行对比。→ 这就是窗口函数：

```sql
select ename, salary, max(salary) over() as 最高薪资
from t_employee;
-- 15 行全保留，每行旁边都挂着同一个"最高薪资 25000"
```

**核心认知：窗口函数每条记录都保留，只是"多算一列"贴回给每一行。**

---

## 二、窗口函数 vs 分组函数（必背区别）

| 对比项 | 分组函数 `max(salary)` | 窗口函数 `max(salary) over(...)` |
|--------|----------------------|----------------------------------|
| 结果行数 | 变少（多行合一） | **不变**（每行都有结果） |
| 能否和普通字段一起 select | 不能（报错） | 能 |
| 典型场景 | 统计报表 | 排名、对比、累计、环比 |

> 分组函数也叫聚合函数、多行函数；窗口函数也叫 OLAP 函数（联机分析处理）。

---

## 三、语法：万能模板

```
窗口函数(参数) over(
    [partition by 分组字段]   -- ① 切窗口：把大表切成几个小组（相当于 group by，但不合并行）
    [order by 排序字段]       -- ② 窗口内排序（配合 sum 会出现累计效果）
    [rows between 起点 and 终点]  -- ③ 手动指定"算哪几行"（进阶，90% 场景用不到）
)
```

**写窗口函数时，按顺序问自己 3 个问题：**

1. **我要算什么？** → 选函数（排名用 rank 三兄弟，统计用 sum/avg，取值用 lag/lead...）
2. **按什么分组？** → 填 `partition by`（不填 = 全表一个窗口）
3. **组内按什么顺序？** → 填 `order by`（不填 = 窗口内不排序）

---

## 四、over() 三个零件的详细拆解

### 零件①：partition by —— 切窗口

```sql
-- 没写：全表算一个窗口，每行都是同一个"全公司平均"
select ename, did, salary,
       avg(salary) over() as 全公司平均
from t_employee;

-- 写了：每个部门各算各的
select ename, did, salary,
       avg(salary) over(partition by did) as 部门平均
from t_employee;
```

> 对比记忆：`partition by` 像 `group by`，但 `group by` 合并行，`partition by` 不合并行。
> 细节：`partition by did` 时，did 为 NULL 的记录会**自成一组**，不会消失。

### 零件②：order by —— 窗口内排序（配合 sum 出累计）

```sql
select ename, salary,
       sum(salary) over(order by salary) as 累计薪资
from t_employee;
-- 薪资升序，每行累加：6800 → 14600 → 22600 → ... → 总和
```

**为什么会有"累计"效果？—— 隐藏默认窗口范围（本笔记最重要的一句话）：**

| 写法 | 等价于 | 默认窗口范围 |
|------|--------|-------------|
| `over()` | — | 整个窗口（全表/整个分区） |
| `over(order by ...)` | `over(order by ... rows between unbounded preceding and current row)` | **从起点到当前行**（累计效果） |

**累计方向跟着 order by 方向走：**

```sql
-- 降序 = 从最高薪开始往下累加（最后一行 = 全公司薪资总和）
select ename, salary,
       sum(salary) over(order by salary desc) as 逆序累计
from t_employee;
```

**partition by + order by 组合 = 每个部门内做累计：**

```sql
select ename, did, salary,
       sum(salary) over(partition by did order by salary) as 部门内累计
from t_employee;
```

### 零件③：rows between —— 自己定义"算哪几行"（进阶）

只有默认范围不满足需求时才用。语法：

```sql
rows between 起点 and 终点
-- 起点/终点可选值：
--   unbounded preceding   窗口第一行
--   n preceding           当前行之前 n 行
--   current row           当前行
--   n following           当前行之后 n 行
--   unbounded following   窗口最后一行
```

**例：移动平均（只看当前行和前 1 行）：**

```sql
select ename, salary,
       avg(salary) over(order by salary
                        rows between 1 preceding and current row) as 近两行平均
from t_employee;
-- 第 1 行只有自己；第 2 行开始 = "自己 + 上一行"的平均
```

## 五、排名三兄弟（最常用、面试最爱考）

```sql
select ename, did, salary,
       row_number() over(partition by did order by salary desc) as rn,
       rank()       over(partition by did order by salary desc) as rk,
       dense_rank() over(partition by did order by salary desc) as drk
from t_employee
where did is not null;
```

以"市场部两个 12000 并列"为例：

| 员工 | salary | row_number | rank | dense_rank |
|------|--------|-----------|------|------------|
| 王芳 | 18000 | 1 | 1 | 1 |
| 陈静 | 12000 | 2 | **2** | **2** |
| 赵敏 | 12000 | 3 | **2** | **2** |
| 吴婷 | 7800 | 4 | **4** | **3** |
| 褚健 | 6800 | 5 | **5** | **4** |

**区别表（必背）：**

| 函数 | 并列怎么排 | 下一个跳号吗 |
|------|-----------|-------------|
| `row_number()` | 并列也硬排 1、2、3 | 不跳 |
| `rank()` | 并列相同 | **跳号**（2、2、**4**） |
| `dense_rank()` | 并列相同 | **不跳**（2、2、3） |

> 记忆口诀：**row_number 像点名（一个不落）；rank 像奥运奖牌（并列金银，没有第 2 就跳过去）；dense_rank 像"并列都算第 2 名，下一个还是第 3 名"。**

**经典题：取每个部门薪资前 3 名 → 必须用 dense_rank，且要套子查询：**

```sql
select * from (
    select ename, did, salary,
           dense_rank() over(partition by did order by salary desc) as rk
    from t_employee
) t
where t.rk <= 3;
```

**为什么不能直接写 where rk <= 3？** 因为 `where` 在窗口函数**计算之前**执行，看不到排名结果。必须先算（子查询），再在外层筛选。

**为什么用 dense_rank 而不用 rank？** rank 跳号会漏人：并列第 2 有两个，下一个就是第 4 名，`where rk<=3` 会漏掉真正的"第 3 高"。

## 六、聚合窗口函数（sum / avg / min / max + over）

### 例 1：每个部门的平均薪资 vs 全公司的平均薪资（文档经典例子）

```sql
select distinct
    did,
    avg(salary) over(partition by did) as 部门平均,
    avg(salary) over() as 全公司平均,
    round(avg(salary) over(partition by did) - avg(salary) over(), 2) as deviation
from t_employee;
```

- `avg(salary) over(partition by did)` → 每个部门一个平均值
- `avg(salary) over()` → 每行都是同一个全公司平均值
- 相减 → 每个部门比公司平均高/低多少

### 例 2：文档案例——"员工薪资高于 15000 的男员工，姓名处理成 张xx"

```sql
select rpad(left(ename, 1), 3, 'x'), salary
from t_employee
where salary > 15000 and gender = '男';
```

> 注意：`left(ename,1)` 取姓，`rpad(...,3,'x')` 右填充到 3 位 → 张xx。这不是窗口函数，是字符串函数组合，放这里提醒你别搞混。

## 七、取值函数：lag / lead / first_value / last_value

**用途：取"上一位/下一位/首位/末位"的值，做环比、差值对比。**

```sql
select
    ename,
    salary,
    lag(ename, 1, '-') over(order by salary) as 上一位姓名,   -- 取上一行，没有则显示 '-'
    lag(salary, 1, 0) over(order by salary) as 上一位薪资,    -- 取上一行薪资，没有则 0
    lead(ename) over(order by salary) as 下一位姓名,
    lead(salary) over(order by salary) as 下一位薪资,
    first_value(salary) over(order by salary) as 首位薪资,    -- 窗口第一行
    last_value(ename) over(order by salary
        rows between unbounded preceding and unbounded following) as 末位姓名  -- 窗口最后一行
from t_employee;
```

**参数格式：`lag(字段, 偏移量, 默认值)` / `lead(字段, 偏移量, 默认值)`**

- 偏移量默认 1（上一行/下一行）
- 默认值：越界时显示什么（NULL 会很难看，通常给个占位）

> ⚠️ 坑：`last_value` 默认只看到"当前行"（受 `over(order by ...)` 默认范围影响），要取真正的"窗口最后一行"，必须显式写 `rows between unbounded preceding and unbounded following`。

## 八、window 给窗口起别名（语法糖）

一个窗口配置被多个函数复用时，用 `window` 关键字起个别名，少写重复代码：

```sql
-- 不用 window
select ename, did, salary,
       row_number() over(partition by did order by salary) as rn,
       rank()       over(partition by did order by salary) as rk,
       dense_rank() over(partition by did order by salary) as drk
from t_employee where gender = '女';

-- 用 window（等价）
select ename, did, salary,
       row_number() over w as rn,
       rank()       over w as rk,
       dense_rank() over w as drk
from t_employee where gender = '女'
window w as (partition by did order by salary);
```

## 九、常见应用场景速查

| 场景 | 用什么 | 例子 |
|------|--------|------|
| 部门内排名 | rank 三兄弟 + `partition by did order by ...` | 每部门薪资前 3 |
| 全公司排名 | rank 三兄弟 + `order by ...`（不写 partition by） | 公司薪资榜 |
| 部门平均 vs 全公司平均 | `avg() over(partition by did)` + `avg() over()` | 找部门差距 |
| 累计求和 / 营收曲线 | `sum() over(order by ...)` | 从高到低累计 |
| 上一位 / 下一位对比 | `lag()` / `lead()` | 环比涨跌 |
| 移动平均 | `avg() over(order by ... rows between n preceding and current row)` | 近 N 笔平均 |

## 十、易错点总结（全踩过一遍就不会再错）

1. **`where` 用不了窗口函数结果** → 必须套子查询再筛。
2. **取前 N 名用 `dense_rank`** → `rank` 跳号会漏人。
3. **`over(order by ...)` 有默认范围"从起点到当前行"** → 所以 sum 会累计；last_value 会被"截断"。
4. **`partition by` 的 NULL 自成一组** → 想要排除就加 `where 字段 is not null`。
5. **窗口函数结果直接和普通字段混用没问题** → 它不改变行数。
6. **`rows between` 平时不用管** → 只有移动平均、累计占比等场景才需要。

## 十二、学习路线建议

1. **第一步**：玩熟排名三兄弟（row_number / rank / dense_rank）+ partition by + order by
2. **第二步**：聚合函数 + over（sum/avg/min/max），搞懂"累计"为什么出现
3. **第三步**：lag / lead / first_value / last_value（环比、差值）
4. **第四步**：最后才碰 rows between（移动平均等）

> **心法：窗口函数 = 分组函数 + over(窗口)。先无视 rows between，把 partition by 和 order by 玩明白，就学会了 80%。**
