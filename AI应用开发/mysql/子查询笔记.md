# 子查询 完整笔记

> 对应《尚硅谷大模型技术之 MySQL2.0》"子查询"章节（含通用表达式 CTE）
> 配套数据：`atguigu` 库的 `t_employee`（员工表）、`t_department`（部门表）、`t_job`（职位表）
> 练习前先执行：`use atguigu;`

---

## 一、子查询是什么？

**一句话：嵌套在另一个 SQL 语句里面的查询。**

```sql
select ename, salary
from t_employee
where salary = (select max(salary) from t_employee);  -- ← 括号里这个就是子查询
```

- **外层** = 主查询（外面的 select）
- **内层** = 子查询（括号里的 select）
- **执行顺序：子查询先执行 → 算出结果 → 外层拿这个结果继续查**

**本质**：子查询就是"**先查出一个结果，再用这个结果做条件**"。

> 🎯 **子查询和 select 7 子句的关系**（本笔记已拆出，详见《select七子句笔记.md》）：子查询是"零件"，可以插进 7 子句这个"骨架"的不同位置——select 里（当列）、where/having 里（当条件）、from 里（当临时表）、甚至 update/delete 里（当值/条件）。**你在第一部分学过的所有子句，都可能被套上一个子查询。**

---

## 二、三种"结果形状" → 决定写法（最重要的分类）

子查询返回的结果**长得不一样，外层写法就不一样**：

| 子查询结果 | 外层怎么用 | 例子 |
|-----------|-----------|------|
| **单行单列**（1 个值） | 比较运算符 `= > < >= <= !=` | `salary = (select max(salary) ...)` |
| **单列多行**（一列多个值） | `in` / `not in`，或 `any` / `all` | `did in (select did ...)` |
| **多行多列**（一张小表） | 放 `from` 后面当临时表 | `from (select ...) temp` |

**记法**：**"一个值 → 比较；一串值 → in；一张表 → from"**。

**拿到题第一步永远先问**：子查询返回的是"一个值 / 一串值 / 一张表"？答案决定写法。

---

## 三、select 中嵌套：子查询当"一列"用

子查询结果是一个值，直接当一个**字段**输出：

```sql
-- 每个人薪资和公司平均薪资的差值，显示相差 5000 以上的
select
    ename as "姓名",
    salary as "薪资",
    round((select avg(salary) from t_employee),2) as "全公司平均薪资",
    round(salary - (select avg(salary) from t_employee),2) as "差值"
from t_employee
where abs(round(salary - (select avg(salary) from t_employee),2)) > 5000;
```

**特征词**：想在结果里**多显示一列"对比值"**（平均、最大、上期值……）→ select 嵌套。

**要点**：
- `(select avg(salary) from t_employee)` 算出一个值，每行都拿它用
- **缺点：同一个子查询可能写 3 遍**（重复代码多）→ 第 9 节的 CTE 就是为治这个病

**经典用法：按薪资编号（子查询当计数器）**

```sql
select
    ename, salary,
    (select count(*) from t_employee as temp2 where temp1.salary > temp2.salary) as rk
from t_employee as temp1
order by rk;
```

**讲解**：这是**关联子查询**（子查询里用了外层表的 temp1）——对每一行 temp1，数一数"全公司有几个人工资比我低"，这个数就是排名。

## 四、where / having 中嵌套（最常用）

**特征词**：条件本身**要先查出来**（"薪资=最高的人""和 XX 同部门的人"）→ where/having 嵌套。

#### 单值 → 比较运算符

```sql
-- 薪资最高的员工
select ename, salary
from t_employee
where salary = (select max(salary) from t_employee);
-- 先算：max(salary)=25000；再查：谁 salary=25000 → 张伟

-- 比平均薪资高的男员工
select ename, salary
from t_employee
where salary > (select avg(salary) from t_employee)
  and gender = '男';
```

#### 多值 → in / not in

```sql
-- 和 张伟、王芳 同一部门的员工姓名和电话
select ename, tel, did
from t_employee
where did in (select did from t_employee where ename='张伟' or ename='王芳');
```

**执行过程**：
```
第 1 步：子查询算出 张伟、王芳 的 did → 结果 (1, 2)
第 2 步：外层等价于 where did in (1, 2)
第 3 步：所有 did=1 或 did=2 的员工都查出来
```

#### 多值 → any / all（比"任一"或"所有"）

```sql
-- 比 张伟、王芳、陈静 三个人的薪资都要高（all = 比所有都高）
select ename, salary
from t_employee
where salary > all(select salary from t_employee where ename in ('张伟','王芳','陈静'));
-- 等价于：salary > (select max(salary) ...)

-- 比其中"任意一个"高（any = 比任一高）
select ename, salary
from t_employee
where salary > any(select salary from t_employee where ename in ('张伟','王芳','陈静'));
-- 等价于：salary > (select min(salary) ...)
```

**记忆**：
- `salary > all(子查询)` = 大于子查询结果里的**最大值**（比所有都高）
- `salary > any(子查询)` = 大于子查询结果里的**最小值**（比任意一个高）

> 实际工作中 `all`/`any` 用得少，大家更喜欢直接写 `max`/`min` 子查询或 `in`。但面试会问，理解含义即可。

#### having 中嵌套

```sql
-- 部门平均薪资 > 全公司平均的部门（编号、名称、平均薪资），按平均升序
select t_department.did, dname, avg(salary)
from t_employee
right join t_department
on t_employee.did = t_department.did
group by t_department.did
having avg(salary) > (select avg(salary) from t_employee)
order by avg(salary);
```

**要点**：having 里也能放子查询（子查询算出一个值，跟组的 avg 比较）。规则和 where 一样：**看子查询返回单值还是多值**。

## 五、from 中嵌套：子查询当"临时表"

**特征词**：要**基于另一个查询的结果再查**（排名后筛选、先统计再连接）→ from 嵌套。

**为什么需要它？** where 里只能塞"一个值/一串值"，塞不下"一张表"。当子查询结果是**多行多列**时，就把它放到 `from` 后面**当成一张临时表**用。

#### 例 1：每个部门的平均薪资 + 部门名称

```sql
select t_department.did, dname, pingjun
from t_department
left join (
    select did, avg(salary) as pingjun
    from t_employee
    group by did
) temp                        -- ← 子查询结果当临时表，必须起别名！
on t_department.did = temp.did;
```

**执行过程**：
```
第 1 步：先跑子查询 → 得到临时表 temp（did=1→19400, did=2→11320, did=4→11500, NULL→8500）
第 2 步：把 temp 当成一张普通表，和 t_department 左连接
```

> ⚠️ **铁律：from 后面的子查询必须起别名**（temp），不写直接报错：
> `Every derived table must have its own alias`。**这是 from 嵌套最容易犯的错。**

#### 例 2：每个部门薪资前 2 名（窗口函数 + from 嵌套）

```sql
select *
from (
    select ename, did, salary,
           dense_rank() over (partition by did order by salary desc) as paiming
    from t_employee
) temp
where temp.paiming <= 2;
```

> **为什么 where 不能直接写 `where paiming <= 2`？** 因为 paiming 是 select 阶段（⑥）才生成的窗口函数结果，where（③）根本看不到。必须**先查出来变成临时表，再在外面筛**——这就是 from 嵌套最经典的场景。

## 六、exists 型子查询："存不存在？"

**特征词**："是否存在 / 有没有 / 如果……就" → exists（回答的是 yes/no，不是值）。

#### 和 where 型子查询的本质区别

| | where 型（in/比较） | exists 型 |
|---|---|---|
| 子查询结果 | 返回**值**，拿去比较 | 只看**有没有返回行**（true/false） |
| 结果内容 | 内容重要 | **内容无所谓，有没有行才重要** |
| 工作方式 | 先算子查询，再用结果筛 | 外层每行都"问一遍"子查询 |

#### 场景 1：子查询和外层没关联（简单 exists）

```sql
-- 如果 t_employee 里有 did 为 NULL 的员工，就查部门表
select * from t_department
where exists(select * from t_employee where did is null);
```

**执行逻辑**：
```
第 1 步：跑 exists 里的子查询 → t_employee 有 did=NULL 的员工吗？
        → 有（李红、周洲）→ exists 返回 true
第 2 步：外层"是否执行"由 true/false 决定 → true → 查出所有部门
```

- **exists 返回 true** → 外层正常查
- **exists 返回 false** → 外层一行都不查（结果为空）

> 典型用途：**"如果满足某条件才执行查询"**（类似程序里的 if）。

#### 场景 2：关联 exists（子查询引用外层表）——重点！

```sql
-- 查部门表里"存在员工"的部门（即和员工表有相同 did 的部门）
select * from t_department
where exists(
    select * from t_employee
    where t_employee.did = t_department.did   -- ← 用了外层的 t_department.did
);
```

**执行逻辑（关键，逐行循环）**：
```
MySQL 拿外层 t_department 的每一行，代入子查询"问一遍"：
第 1 行：研发部 did=1 → 子查询问"有员工 did=1 吗？" → 有 → true → 保留
第 2 行：市场部 did=2 → 子查询问"有员工 did=2 吗？" → 有 → true → 保留
第 3 行：测试部 did=3 → 子查询问"有员工 did=3 吗？" → 没有 → false → 丢弃
第 4 行：运维部 did=4 → 子查询问"有员工 did=4 吗？" → 有 → true → 保留
结果：研发部、市场部、运维部（测试部被排除）
```

**文档原话**：*"对外层查询表做循环，在筛选外层查询表的每一条记录时，都看这条记录是否满足子查询的条件，满足就保留，否则丢弃。"*

**结果等价于**：

```sql
select distinct t_department.*
from t_department
inner join t_employee
on t_department.did = t_employee.did;
```

#### 面试常问：exists 和 in 的区别

- `in`：子查询返回**值列表**，拿外层字段去比对（先算出所有值）
- `exists`：子查询返回 **true/false**，外层每行循环问一次（关注"有没有"）
- 数据量小时感觉差不多；exists 常用于"大表驱动小表"优化

## 七、update / delete 中嵌套子查询

**特征词**：改/删数据时，**条件或要赋的值需要先查出来** → update/delete 嵌套。

#### update 中嵌套

**① 子查询在外层 where（当条件）**：

```sql
-- 把测试部员工的薪资改成 1.5 倍
update t_employee
set salary = salary * 1.5
where did = (select did from t_department where dname = '测试部');
```

**② 子查询在 set 后（当要赋的值）**：

```sql
-- 把 did 为 NULL 的员工，did 改成测试部的编号
update t_employee
set did = (select did from t_department where dname = '测试部')
where did is null;
```

> ⚠️ 这种"set = 子查询"必须保证子查询返回**单个值**，否则没法赋值。

**③ ⚠️ 同表 update 的大坑（文档重点）**：

```sql
-- 想把"李冰冰"的薪资改成"孙红梅"的薪资
-- ❌ 报错：You can't specify target table for update in FROM clause
-- 因为 update 和子查询的是同一张表 t_employee
update t_employee
set salary = (select salary from t_employee where ename='孙红梅')
where ename='李冰冰';

-- ✅ 正确：子查询里再套一层，把结果"包"成临时表
-- 让 update 和最外层子查询不是同一张表
update t_employee
set salary = (
    select salary from (
        select salary from t_employee where ename='孙红梅'
    ) temp
)
where ename='李冰冰';
```

**为什么？** MySQL 规定：**update 的表和子查询里直接引用的表不能是同一张**（怕"边改边读"数据错乱）。解法：**把子查询再套一层临时表**，绕开限制。**记住"同表 update 要套两层"这个套路**。

#### delete 中嵌套

```sql
-- 删除测试部的员工（子查询用 t_department，和 delete 的 t_employee 不是同一张表，不报错）
delete from t_employee
where did = (select did from t_department where dname='测试部');

-- ❌ 报错：delete 和子查询都是 t_employee
delete from t_employee
where did = (select did from t_employee where ename='李冰冰');

-- ✅ 正确：套一层临时表
delete from t_employee
where did = (select did from (select did from t_employee where ename='李冰冰') temp);
```

**规律和 update 一样：子查询和主操作是同一张表 → 套临时表。**

## 八、用子查询复制表结构和数据

**① 复制表结构**（只要结构，不要数据）：

```sql
create table department like t_department;
-- like：复制表结构（字段、类型、约束），不复制数据
```

**② 复制数据到已存在的表**（insert + 子查询，此时 insert 不用写 values）：

```sql
insert into department (select * from t_department where did <= 3);
```

**③ 同时复制表结构和记录**（create table as）：

```sql
create table d_department as (select * from t_department);
-- 如果 select 后面是部分字段，复制的新表就只有这一部分字段

-- 按条件复制（最常用）
create table emp as (
    select eid, ename, salary, tel, mid
    from t_employee
    where salary < 10000
);
```

**like vs as 的区别（重点）**：

| 写法 | 复制什么 | 数据 |
|------|---------|------|
| `create table 新表 like 旧表` | 只复制**表结构**（字段/类型/约束） | ❌ 无数据 |
| `create table 新表 as (select ...)` | 按查询结果建表 | ✅ 有数据（可筛选字段/行） |

> ⚠️ `as` 方式**不会复制约束**（主键、自增、默认值），只复制字段和类型——复制出来的表结构"宽松"，需要的话自己再补约束。

## 九、通用表达式 CTE（Common Table Expressions）

#### CTE 是什么？

- **CTE = 命名的临时结果集**，作用范围是**当前语句**
- 可以理解成**可以复用的子查询**，但比子查询更强：
  - 一个 CTE 可以引用**其他 CTE**
  - CTE 可以**递归**（recursive）
  - 可以**在同一查询中多次引用**（子查询做不到）
- 主要解决子查询的**重复代码**问题（第 3 节里"平均薪资写 3 遍"的病）

**语法**：

```sql
with [recursive]
cte_name [(字段名1, 字段名2)] as (子查询),
cte_name [(字段名1, 字段名2)] as (子查询)
select ... from ...;
```

- 以 `with` 开头；加 `recursive` 表示 CTE 需要递归引用自己
- 每个 CTE 都要有名字，相当于子查询结果集的名字

#### 例 1：解决"平均薪资写 3 遍"的问题

```sql
-- 对比第 3 节的例子：那里 (select avg(salary) ...) 写了 3 遍
-- 用 CTE 只写一遍，后面直接用名字
with
temp as (select round(avg(salary),2) as pingjun from t_employee)
select
    ename as "员工姓名",
    salary as "薪资",
    pingjun "公司平均薪资",
    round(salary - pingjun,2) "差值"
from t_employee, temp
having abs(差值) > 5000;
```

**讲解**：`with temp as (...)` 先把"全公司平均"算好命名成 temp，后面 select 里直接用 `pingjun`，不用再写子查询了。

#### 例 2：多个 CTE + 起字段名（员工和领导）

```sql
-- 查询薪资低于 9000 的员工编号、姓名、薪资、领导编号、领导姓名、领导薪资
with
emp as (select eid, ename, salary, `mid` from t_employee where salary < 9000),
mgr(meid, mename, msalary) as (select eid, ename, salary from t_employee)
select
    eid as "员工编号",
    ename as "员工姓名",
    salary as "员工薪资",
    meid as "领导编号",
    mename as "领导姓名",
    msalary as "领导薪资"
from emp join mgr on emp.mid = mgr.meid;
```

**讲解**：
- 两个 CTE 用逗号分隔：`emp`（低薪员工）、`mgr`（所有员工当领导表）
- `mgr(meid, mename, msalary)` 是**给 CTE 的列起新名字**（把 eid→meid、ename→mename），避免和外层列名混淆

#### 例 3：递归 CTE（查员工的所有领导，直到最高领导）

```sql
-- 先建一张多层领导关系的表（emp 里 eid 是 21→19→17→16→15→4 的链条）
create table emp as (select eid, ename, salary, tel, `mid` from t_employee where salary<10000);
update emp set mid=19 where eid=21;
update emp set mid=17 where eid=19;
update emp set mid=16 where eid=17;
update emp set mid=15 where eid=16;
update emp set mid=4  where eid=15;
update emp set mid=null where eid=4;

-- 递归：从 eid=21 出发，一路向上找领导，直到 mid 为 NULL
with recursive
cte as (
    -- 锚点：先查起点（21号员工自己）
    select eid, ename, `mid`
    from emp
    where eid = 21
    union all
    -- 递归部分：拿 cte 里已有的 mid，再去 emp 里找对应的员工
    select emp.eid, emp.ename, emp.mid
    from emp join cte
    on emp.eid = cte.mid
    where emp.eid is not null
)
select * from cte;
```

**讲解**：
- `with recursive`：声明递归
- **锚点成员**（union all 上面部分）：初始结果，查起点 21 号员工
- **递归成员**（union all 下面部分）：拿当前结果集 cte 的 mid，去 emp 表里找 eid 相等的员工，循环直到找不到
- 结果：21 → 19 → 17 → 16 → 15 → 4 一整条领导链

> 递归 CTE 是进阶内容，了解"递归 = 锚点 + 递归成员 + union all"这个结构即可，用到再深入。

## 十、易错点总结

1. **from 后面的子查询必须起别名**：`from (select ...) temp`，否则报 `Every derived table must have its own alias`
2. **where 用不了窗口函数/别名**：要先 from 嵌套包一层再筛
3. **update/delete 与子查询同表**：必须再套一层临时表，否则报错
4. **`set = 子查询` 必须返回单值**：多值无法赋值
5. **exists 关注"有没有行"**，不关注内容；关联 exists 是逐行循环
6. **`in` vs `exists`**：in 用值列表比对，exists 用 true/false 判断
7. **create table as 不复制约束**（主键、自增等），只复制字段类型
8. **子查询结果形状决定写法**：单值→比较、多值→in/any/all、多列→from/CTE

**题 4**：查询薪资**比市场部（did=2）所有员工都高**的非市场部员工（用 all）

<summary>答案</summary>

```sql
select ename, salary
from t_employee
where salary > all(select salary from t_employee where did = 2)
  and did <> 2;
-- 也可写成：salary > (select max(salary) from t_employee where did=2) and did<>2
```
</details>

**题 5**：用 from 嵌套，查询薪资高于全公司平均薪资的员工

<details>
<summary>答案</summary>

```sql
-- 简单写法（where 嵌套）
select ename, salary
from t_employee
where salary > (select avg(salary) from t_employee);

-- from 嵌套写法
select e.ename, e.salary
from t_employee e
join (select avg(salary) as a from t_employee) t
on e.salary > t.a;
```
</details>

**题 6**：用 exists 查询**有员工的部门**（部门编号、名称）

<details>
<summary>答案</summary>

```sql
select did, dname
from t_department
where exists(
    select * from t_employee
    where t_employee.did = t_department.did
);
```
</details>

**题 7**：把薪资低于 9000 的员工复制到新表 `t_emp_low`

<details>
<summary>答案</summary>

```sql
create table t_emp_low as (
    select eid, ename, salary from t_employee where salary < 9000
);
```
</details>

**题 8**（进阶）：查询**每个部门**薪资最高的员工

<details>
<summary>答案</summary>

```sql
select *
from (
    select ename, did, salary,
           dense_rank() over (partition by did order by salary desc) as paiming
    from t_employee
) temp
where temp.paiming = 1;
```
</details>

## 十二、学习路线

1. **先记三种结果形状**：单值→比较、多值→in/any/all、多列→from/CTE
2. **where/having 嵌套**：最常用，先练熟（单值比较 + in）
3. **select 嵌套**：当"列"用，注意重复代码问题（引出 CTE）
4. **from 嵌套**：当"临时表"用，记住必须起别名；窗口函数排名靠它筛
5. **exists**：理解"逐行问一遍"的循环模式，能说出和 in 的区别
6. **update/delete 嵌套**：记住"同表套临时表"的坑
7. **CTE**：把重复子查询抽成命名结果集；递归 CTE 了解结构即可

> **心法：子查询 = "先查出一个结果，再拿它去用"。拿到题先判断子查询结果是什么形状，再决定放哪、怎么写。**
